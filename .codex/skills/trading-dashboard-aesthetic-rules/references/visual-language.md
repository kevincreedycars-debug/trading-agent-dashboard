# Visual Language

## Intent

Create a dashboard that feels like a serious market workstation. The interface should feel fast, sharp, and information-dense without becoming noisy or theatrical.

## Core Look

- Use near-black or deep-slate base surfaces.
- Layer panels with subtle tonal separation instead of bright cards on bright backgrounds.
- Introduce atmosphere with restrained gradients, faint grid textures, and soft glows rather than large illustrations.
- Keep borders thin and crisp.

## Color System

- Use cool neutrals for structure and text.
- Reserve green for constructive or bullish states.
- Reserve red for bearish, failed, or risk states.
- Reserve amber for caution, timing sensitivity, or partial trust.
- Reserve blue or teal for navigation, selection, and live-system emphasis.
- Avoid pastel palettes and warm cream backgrounds.

## Typography

- Use a strong sans family for headings.
- Use a legible sans family for body copy.
- Use mono selectively for timestamps, labels, pills, and market-like metadata.
- Keep headings compact and confident.
- Avoid ornate serif presentation.

## Layout Behavior

- Organize content into compact, high-contrast panels.
- Favor horizontal scan paths for live telemetry and key signal summaries.
- Treat spacing as controlled compression: generous enough to read, tight enough to feel like a desk tool.
- Allow visual density to increase deeper in the page, but keep the top of the page immediately legible.

## Truthfulness Rules

- Do not use dramatic visual treatment to overstate confidence in frozen or invalidated research.
- Make warnings, caveats, and downstream-only constraints easy to see.
- When presenting research, reinforce that it is context, not live edge, unless the underlying logic explicitly supports otherwise.

## Reuse Rule

Before changing any visual artifact in this repo, align the work to this file first. If a proposed design choice conflicts with this rule set, update the design choice rather than silently drifting away from the contract.
