USD · Layer 1 · Call Map

How the USD Layer 1 call is made

One snapshot becomes one 24-hour dollar call: eight workflow steps, ten weighted factors, one deterministic score. The model describes the evidence; the code fixes the call.

  • rulebook agent_usd_direction.md · v2.1
  • model gpt-4.1-mini
  • horizon 24H · also 3d / week / next / month
  • same snapshot → same call

Step 1 — the run

Eight steps, one snapshot, one row

The orchestrator triggers the workflow. It reads the newest usable USD snapshot, fetches its own rulebook, asks the model to describe the factors, then re-scores them in code and writes one row to agent_outputs.

  1. 01 · TRIGGERWhen Executed by Another WorkflowThe refresh orchestrator calls the USD agent.
  2. 02 · READSupabase Get ManyReads every row of the market_snapshots table.
  3. 03 · PACKBuild USD Input PackKeeps the newest snapshot that passes the 14-field USD usability test.
  4. 04 · RULEBOOKGet USD Logic DocumentGitHub read of logic/agent_usd_direction.md.
  5. 05 · MODELMessage a modelgpt-4.1-mini reads rulebook + snapshot, asked to classify factors as JSON.
  6. 06 · PARSEParse USD Agent OutputReads the model JSON into the row contract; flags missing inputs.
  7. 07 · SCORECalculate USD ConvictionRe-derives every factor from the snapshot and computes the call.
  8. 08 · WRITECreate a rowWrites the finished call to agent_outputs.

Step 3 — the score

How the ten votes become the call

  1. Add each factor's weight under its vote → bullish, bearish and neutral weight.
  2. Participation = bullish + bearish (the directional share of 100).
  3. Bull case % = round(bullish ÷ participation × 100); bear case % mirrors it. Net edge = bull − bear.
  4. The heavier side wins (BULLISH / BEARISH); a tie is NO_CLEAR_BIAS; |net edge| < 20 softens it to BULLISH_LEAN / BEARISH_LEAN.
  5. Conviction = the winning side's case % (0 for NO_CLEAR_BIAS) — a share of active weight, not a win chance.
  6. |net edge| ≥ 40 VERY_STRONG · ≥ 25 STRONG · ≥ 15 MODERATE · else WEAK.
  7. Missing inputs score NEUTRAL: lower participation and conviction, never block a call.

The design guarantees

What is always true

  • One snapshot, one call. Reads only its own rulebook + the newest usable USD snapshot; never another agent, Layer 2, or a research file.
  • Code decides; the model narrates. Node 07 re-derives every signal; the model's own direction and conviction never reach the published call.
  • Same facts, same call. Deterministic scoring: one snapshot → one direction and one conviction.
  • Missing data is neutral, not guessed.

Limits, stated on the page itself

Read this page honestly

  • Rulebook header vs code. The v2.1 rulebook lists one weight per factor; the live node uses the per-horizon weights above.
  • The model's numbers are discarded. Node 07 overwrites direction and conviction from the raw snapshot.
  • Input-pack fallbacks. With no usable snapshot the newest row is used; gold / NQ 5-day fall back to 1-day.
  • A published call is not a proven edge. This page shows how the call is made, not whether it is right.
