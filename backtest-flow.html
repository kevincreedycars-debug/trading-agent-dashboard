How backtesting flows into the dashboard

The upper lane is the production chain that produces the Layer 1 and Layer 2 calls you act on. The lower lane is backtesting: a read-only copy of what production already stored, measured and republished as evidence. The two lanes meet on the dashboard screen, and nowhere else.

Lane A · live production

Every refresh: where the Layer 1 and Layer 2 calls come from

Five sealed Layer 1 agents each run on their own logic document. Nothing on this lane reads research, and no Layer 1 agent reads another agent.

  1. 01 · COLLECT Collectors (n8n) Eco Events plus the USD, EUR, Gold, NQ and BTC collectors store one market snapshot per refresh. writes market_snapshots
  3. 02 · STORE Supabase market_snapshots The canonical market context that agents read and research later copies. runtime table
  5. 03 · LAYER 1 Five sealed agents Each agent reads only its own logic document and the latest usable snapshot, then writes one raw 24-hour directional call. writes agent_outputs
  7. 04 · STORE Supabase agent_outputs Raw calls kept exactly as written, separately per asset. runtime table
  9. 05 · LAYER 2 Pair selection Downstream of Layer 1: it reads the finished calls and raises the cross-pair call when two assets oppose. It combines, it does not re-derive. writes layer2.json
  11. 06 · PUBLISH Dashboard Writer → GitHub Pages Publishes layer1.json, layer2.json and the workflow status the browser reads. → Layer 1 tiles · Layer 2 grid
Read-only boundary the only crossing between the two lanes

Backtesting copies the stored tables, the market history and the frozen logic documents. Production never reads a research artifact, so a backtest cannot change a Layer 1 or Layer 2 call, a workflow, or a stored row.

Research may read
agent_outputs · market_snapshots · frozen logic documents · registries · market history
Research may never write
n8n workflows · Supabase runtime tables · live call path · another agent's input

Lane B · backtesting (downstream only)

How a backtest earns the right to be shown

One build order, in this sequence. A step is only trusted after the one before it reproduces the live behaviour it claims to replay.

  1. 01 · COPY Frozen inputs A read-only copy of stored calls, market history, registries and the logic documents as they stood. no live read-write
  3. 02 · REBUILD Snapshot builders Reconstruct exactly the input the agent saw at time T, with vintages and timestamps recorded honestly. parity fixture first
  5. 03 · REPLAY Replay runners Re-run the frozen live logic asset by asset. Assets are never blended, and a parity gate has to pass before anything counts. same rules, new dates
  7. 04 · SCORE Outcome evaluation Score each replayed call against the next 24 hours, with a drift floor so a flat market is not read as a win. hit rate vs drift floor
  9. 05 · CHECK Checker artifacts PASS with 0 fail, 0 missing, 0 tolerance, and the coverage gaps, limits and blocked items recorded next to it. evidence + limits
  11. 06 · PUBLISH Research artifacts Frozen, versioned JSON committed alongside the pages that read it. data/*.json

Lane B lands here · evidence

The dashboard's research readouts

  • Evidence tabs: Backtest / Accuracy, Backtest Engine, Research Proof Map, Factor Edge Lab, Shadow Logic Backtest.
  • Standalone pages: the Gold direction scorecard, Gold backtesting and Gold backtest outcomes read the same frozen artifacts.
  • Read-only. A tab can be reshaped or retired without touching a live call.

Two lanes, one screen: research adds context beside the call, never inside it.

Reading the lines

What this map claims

  • One production chain: collectors write snapshots, five independent Layer 1 agents write raw calls, Layer 2 combines those finished calls, the Dashboard Writer publishes them.
  • One research chain: backtesting copies stored data and frozen logic, replays it, scores it, checks it and publishes artifacts.
  • One crossing: research reads production. Production reads no research, and no Layer 1 agent reads another agent, Layer 2, or a research artifact.

Keep the picture honest

What this map does not claim

  • Not live edge: a passing replay or checker shows history parity for frozen rules on frozen data, not causality, accuracy or profit.
  • Not deployment: a local export or a green test run is not proof that a live workflow changed.
  • Not full coverage: where source vintages or storage timestamps are only proxies, the gap is listed on the research pages instead of being smoothed over.
