## The shared contract, version 1

The contract is in the code and the catalogue, and it is already implemented and guarded. Workstreams B and C
consume it; only workstream A changes it, and only with a catalogue rebuild.

- **Topic** (`catalog.topics[]`): `topic_id` (stable, e.g. `usd-topic-vix-level-and-risk-regime`), `asset`,
  `slug`, `title`, `summary`, `factor_ids[]`, `overlaps[]`, `dispatch` (`state`, optional `task_id`,
  `pack_version`, `context_version`, `prompt_path`, `prompt_sha256`), `companions[]`, `packs[]`, `probes[]`,
  `next_step`, `stages[]`. Six topics cover all twenty-five USD factor entries; every factor sits in at least
  one and a returned report may be mapped to several through its topic, once.
- **Stage** (`topic.stages[]`, exactly three, in order): `stage` (`research`, `red_team`, `adjudication`),
  `order` (1, 2, 3), `label`, `prompt_path`, `prompt_sha256`, `prompt_bytes`, `prompt_source` (`kind`:
  `dispatched_brief` or `generated`), `document_type` (`report`, `review`, `synthesis`), `parent_stage`
  (`null`, `research`, `red_team`), `deliverable`, `returns`.
- **Prompt file**: `docs/research/topics/usd/<slug>/0<order>-<stage-file>-prompt.md`, generated by
  `scripts/build_research_library.js` from the topic map; the catalogue carries its sha256, so the page
  verifies the file before copying it and `topics --check` / `verify` fail on drift. Nothing sends a prompt to
  a model: a reader copies it into their own session.
- **Returned document** (`data/research-library/documents.json`): `document_id`, `asset`, `factor_id` (the
  primary entry), `topic_id`, `stage`, `document_type`, `title`, `model`, `note`, `origin`
  `external_upload`, `storage` `library_object`, `public_download` false, `open_findings[]` (adjudication),
  `parent_document_id`, `parent_version`, `parent_sha256`, `versions[]`. One Markdown file per stage; a
  corrected return becomes the next version of the same `document_id`, and version 1 stays immutable.
- **Stage state** (derived, never asserted): `not_started`, `awaiting_upload`, `delivered`,
  `reassessment_required`. `topicProgress().ready_for_synthesis` is true only when all three stages are
  delivered on the current versions. Ready for synthesis is not a validated rule.
- **Statuses that must not move for a document**: `research_status`, `review_status`, `backtest_status` on the
  factor, and the aggregates (22 ready / 3 blocked, 25 review pending, 25 backtest not tested). An upload is
  evidence; it is not an approval.
- **Storage boundary**: repo-backed documents are published with the site and anyone may View or Download
  them; uploaded evidence lives outside Git under `.local/research-library/objects/` and is readable only
  through the loopback service with its token.
