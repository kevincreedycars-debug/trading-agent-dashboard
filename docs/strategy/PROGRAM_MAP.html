Backtest engine — building now

in progress · gold first

One standalone engine, asset-agnostic, fed asset by asset. Gold is the first asset through it.

  • a every known driver ingested · gold: 28 declared, 16 measured
  • b each driver scored on its influence over 24h, then 5 days
  • c drivers tested against each other → which ones really move price
  • d Layer 1 weights rebuilt from measured influence
  • e new algorithm vs current baseline over 2+ years → direction, L2L, 0.5 L2L

Build it once, reuse it for every asset. It stays downstream: it never feeds the live inputs.

Gates that make it real

  • As-of only: nothing may use information unavailable when the call was made.
  • Descriptive first, predictive later. Overlapping days are not independent trials.
  • Freeze the formula, then test it once on untouched data.
  • Above 60% needs a predeclared lower confidence bound and a baseline beat — a point estimate is not enough.
  • Profit claims need executable evidence: bid/ask, spread, fills, stop ordering.
  • Each new asset needs its own declared contract before it enters the engine.

Not true yet

  • No asset has a qualified 60%+ call.
  • No executable-trade validation exists.
  • 60% is a target, not a guarantee.
  • The bot cannot stand on accuracy alone.
  • More coverage is not more evidence.

Decision queue

  • Phase 1 — the 3 gold-return drivers: go or hold.
  • How a flat / neutral day is defined for the call.
  • Whether delayed endpoints count as eligible outcomes.
  • Dollar index: license a real DXY, or re-declare the broad index under a new name.
  • Calendar: keep archive-inferred, or chase provider evidence.
