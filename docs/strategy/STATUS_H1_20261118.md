The dirty-tree contribution is separate and larger in one respect: with the untracked `h1_evidence.js` and the modified

## 7. Rule issues, the proposal set, and why performance stays unscored

The frozen package is intact and still reproduces: inputs `144ae500…`, rows `47aa93fc…`, archive `1c82e904…`, scoring
contract `bff55b51…`, marked `FROZEN_BEFORE_SCORING`. Six proposals are written against it and none is applied.

**The ICE timing defect, which is first because it silently empties the sample.** v0.1.0 assesses the ICE US Dollar Index
fixing with `max_age_hours = 0` (`inputs.json` → `ice`, fourth element) and requires
`observed_at ≤ published_at ≤ received_at ≤ cutoff` (`lib/layer1_backtesting/h1_candidate.js:59-63`, mirrored in the
package's `engine.js`). With a zero window the three clocks are forced onto the cutoff instant itself, so the only row
that can pass is a synthetic one where all three clocks are equal to the cutoff — which is exactly what the package's own
accepted fixture does (`verify.js:10`). Every real collection is rejected, as `invalid or late clock` if a clock is past
the cutoff and as `stale` if the fixing is from an earlier day. That is not a rare edge: a 05:00 fixing cannot be received
at or before 05:00, so on a strict reading no real morning can ever satisfy the rung. The proposal test drives the
unmodified v0.1.0 package to prove exactly this: v0.1.0 accepts only the all-clocks-on-cutoff fixture, blocks a receipt
that is four seconds late, and blocks a prior-day fixing, while the proposal accepts all three.

**The Monday arithmetic, which is why the cap is 96 hours and not 24.** The 725 sessions contain 579 one-day gaps and 145
three-day Monday gaps, with no holiday gaps, so 145 of 725 mornings (20.0%) follow a weekend
(`tmp/monday-gaps-20261118.json`, computed read-only from `run-v1.json`). A 24-hour maximum age structurally excludes every
Monday morning; a 96-hour maximum keeps Monday and still refuses anything older than the weekend. P-01 therefore defaults
to Option B, 96 hours, with Option A (24 hours) documented as the strict alternative and its Monday cost stated in the
proposal.

The other five proposals are narrower and mostly wording or status: P-02 the front-end as a spread operand, P-03 the VIX
row retitled level-only, P-04 the F23 distance declared unimplemented, P-05 the trace field name and counted vote set, P-06
the calendar admissibility wording. The proposal suite is 13 of 13 and includes a frozen-package guard, the 96-hour
boundary, a summer-DST case and a mirror-consistency check between the prose and
`proposals/H1_V0_1_1_PROPOSALS_20261118.json`. All six stay `proposed_not_applied` until the owner decides; the decision
sheet is section 8 of `V0_1_1_PROPOSALS_20261118.md`.

Performance is unscored and stays unscored. With 0 of 725 mornings eligible there is no evidence set to score, and
scoring a morning built on substituted or proxy data would break the rule that a decision needs an original observation
with three clocks. The four-test verdict and the sealed replay are therefore about reproducibility, not returns: the
morning payload replays byte for byte (`1f10940c…`), the screen payload's modelled content is unchanged, and the v0.1.0
replay of historical decisions reproduces its 725 blocked records with no outcomes.

```

```

then `http://127.0.0.1:4174/backtesting.html`. Driven in headless Chromium with Playwright
(`tmp/preview-check.js 4174`), the page returns 200, the payload returns 200, the tab strip renders, and the H1 view

the screenshot is `tmp/preview-20261118.png` (141,490 bytes) and the JSON record is `tmp/preview-check-20261118.json`.
The server was stopped afterwards; the port is free.

**Not proven, hosted.** The public site serves `main`, and the H1 coverage page is not on `main`. Publishing needs one of
two decisions, and either way it is a publisher action: this lane has no write rights to `main` and did not attempt a
deploy.

1. Keep the standalone page. Merge this branch's `backtesting.html` and its payload to `main`, restore the navigation
   link that 1fdf59b6 removed, rebuild the payload on a clean tree, and let Pages deploy. Verify afterwards that
   `/backtesting.html` returns 200, that `data/usd-layer1-backtester/backtesting-screen-v1.json` returns 200 instead of
   404, and that the coverage line reads 0 of 725.
2. Move the coverage into the tab. Port the H1 view into `#usdLayer1BacktesterView` in `index.html`, retire the
   standalone page and its link test, rebuild the payload, and deploy the same way. This is the smaller long-term change
   and the one that matches where `main` has gone, but it is more code than option 1.

Whichever is chosen, the payload rebuild must happen after the working tree is clean: rebuilding now would capture the
other worker's unfinished `h1_evidence.js` and the modified `h1_coverage.js`, and would publish a rung result nobody has
reviewed.
