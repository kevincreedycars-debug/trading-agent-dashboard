# Prompt-template integration and coverage

Status: local branch work, not deployed. Nothing on the published page, the live collector or the
engine changes because a prompt file changes.

## What this note answers

The coordinator reported seventy-eight chain prompts. An earlier session reported eighteen topic
prompts. Both counts were right about their own branch and neither described the same set of files.
This note states which prompts are rendered by which generator, what was merged, what the generated
files actually say, and what the main coordinator has to do to adopt it.

| 18 | `workstream/c-research-programme` at `3ab05b17` | 6 topic labels x 3 stages under `docs/research/topics/usd/` | `lib/research_prompt_templates.js` at `research-prompt-v3.0.0` |
| 78 | `research/usd-session-20261013` at `1e6ab197` | 25 factor chains x 3 + 3 final stages under `docs/research/factors/usd/` and `docs/research/final/usd/` | inline text in `scripts/build_research_library.js`; no template module on that branch |

The two branches diverged at `3df245a8`. The coordinator then refactored the library from six topics
to twenty-five factor chains plus a gated final chain (`4d5d523f`, `1e6ab197`), which deleted the
topic-stage prompt files and replaced them with the seventy-eight chain prompts. The eighteen were
therefore superseded rather than extended: the unit of work moved from "a topic" to "a factor chain".

Evidence for the generator split, measured on `1e6ab197` before the merge: `lib/research_prompt_templates.js`
does not exist there, no prompt carries a template version, and the seventy-eight files contain 202
occurrences of the phrase `stage card` and 5 of `research card`. Those are instructions the template
forbids, so none of the seventy-eight used the corrected templates.

## What now uses `research-prompt-v3.0.0`

After merging `research/usd-session-20261013` into this branch:

- 78 of 78 chain prompts are rendered by `lib/research_prompt_templates.js` at `research-prompt-v3.0.0`,
  including the three final-chain stages (kind `asset_synthesis`).
- 0 prompts are generated by the old inline path. The six inline prompt functions and their helpers were
  deleted from the builder; the builder now supplies facts and calls `Prompts.buildStagePrompt`.
- The eighteen topic prompts no longer exist. Their content is not the wording of record, and the files
  are deleted rather than left as a second route.

The four defects the coordinator named are therefore absent from the files, not only from the
generator's assertions:

1. **Obsolete four-step process**: the phrase does not occur. The stage sequence is stated once per
   prompt, in the assignment line and the `What happens next` section, and it is three stages.
2. **Card instructions**: the phrase does not occur. The prompt asks for one Markdown file with a fixed
   section list and forbids a card, a JSON payload and a second file.
3. **Duplicate briefs**: the VIX stage 1 prompt names
   `docs/research/handoff/usd/v1/deep-research/VIX_COMPREHENSIVE_REPORT_BRIEF.md` with its sha256 and
   says it must not be followed or answered. The brief body is not pasted; no long line of it survives in
   the prompt. That one file is the whole assignment.
4. **Conflicting deliverable requirements**: each prompt names one file, fixed sections and one
   checklist, and the catalogue's stage metadata now describes those same sections. The final
   adjudication states the candidate Layer 1 logic for isolated backtesting as a named section instead
   of a promise in the catalogue with no counterpart in the prompt.

The catalogue guard is `tests/research_library.test.js`, which re-reads all seventy-eight files, checks
their hashes, the template version label, the ten section titles, the absence of every forbidden phrase
and the presence of the exact deliverable file name the prompt asks for.

   `verify`: that re-registers documents against working-tree bytes and creates new versions for files

## Draft asset profiles

All seven draft profiles now carry an asset-specific `factor_mapping` and, where instrument choice
matters, an `instruments` list. `NQ` carries the three-way distinction explicitly:

- the **Nasdaq-100 index** is a calculation over constituent prices, not a fillable quote, with no
  overnight print;
- the **NQ future** trades nearly round the clock with an expiry, a roll and a basis;
- the **QQQ ETF** trades only in US regular hours, has a premium or discount to net asset value, pays
  distributions and charges an expense ratio, and is what the live collector stores today.

Each states what its return contains and why it is not interchangeable. The profile also records that
`live.f10-equity-versus-usd` is circular for a Nasdaq label and therefore does not transfer. Every
mapping that is not settled is marked `unresolved: true`, and the prompt that carries them says so in
words. No sign, threshold or window is asserted for any draft asset.
