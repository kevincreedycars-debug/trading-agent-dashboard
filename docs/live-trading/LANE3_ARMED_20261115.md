## 2. Two code changes shipped before the arming

Both were found by the owner's own second instruction — "verify that Friday's unplaced EURUSD setup expires across
the closure and that a fresh post-open M5 deviation is required. If the deployed runner needs the lane-3 fix, test and
deploy it now."

**A deviation expires with the session that made it** (`lib/l2l_strategy.js`, commit `43c48316`). The rule already
held all three legs to one session, but the session it compared them against was the *judged candle's own*: on the
Sunday after the dry run, the newest closed EURUSD candle was Friday's 21:50Z close, so Friday's legs agreed with
Friday's candle and the lane stated a buy limit at 1.10203 with no market open to fill it. `buildPlan` now refuses a
deviation whose newest closed candle belongs to an earlier trading session (`Europe/Prague`) than the run, when the
caller states the instant: the row is `waiting`, no plan is stated, and the deviation carries `missing: "expired"`
with both session keys. A fresh crossing completed after the open is required. A market that trades through the
weekend — BTCUSD on this lane — is judged on its own current closes and is unaffected.

**The task runs at `Highest`** (`scripts/register-live-trading-trader-task.ps1`, commits `b55834a0` and `12a6c111`).
The first armed tick at `20:01:30Z` was refused — not because the terminal was wrong, but because the order tool could
not read the private identity file: `identity_missing … Permission denied`. The file is ACL'd to `Administrators` and
`SYSTEM` with inheritance removed, and a task registered at the engine's default run level holds the filtered token in
which `Administrators` is deny-only. Lane 2's file inherits `BUILTIN\Users` read, which is why its `Limited` task has
never hit this. The registration now takes `-Elevated`, which names the same interactive user at `RunLevel Highest`,
and resolves that account to its SID *before* anything is unregistered — the first attempt at this ran over SSH, where
`USERDOMAIN`/`USERNAME` are empty, and the engine removed the old task and then refused the new one, leaving the lane
with no trader for a minute. That near-miss is why the account now comes from the Windows token and is validated
first.

Deployed from `live-trading/l2l-blind-20261114` to `C:\ftmo3` by fast-forward; the deployed blobs were compared with
the branch's own (`lib/l2l_strategy.js` `aa484cb2…`, the registration script `46d5914f…`, the runner unchanged at
`e3bc8fe8…`). `npm test` on the worktree: 959 tests, 7 failures, every one of them pre-existing on this branch and
shown to fail identically with the change stashed (page-render, chart pan/zoom, walkthrough-number and
research-library browser tests). The lane's own suites — `l2l_strategy`, `live_trading_blind_lane`,
`live_trading_deviation_sequence`, `live_trading_trader`, `live_trading_lane_isolation`, `live_trading_order_tool` —
pass in full, and `tests/live_trading_blind_lane.test.js` passes 16 of 16 on the deployed checkout itself.

## 7. What is not proved

- **Nothing has been bought or sold.** The lane has stated no ticket in any armed tick, so a placement, a fill, the
  2R breakeven, the 3R trail, a cancel of an unfilled limit and the exit path are all still unexercised on this
  account. A healthy waiting tick is what the owner asked for as sufficient; the first real setup is the first proof
  of the send path. *Since written:* the market answered that on 2026-11-16 and again on the 18th — three limits
  filled and three stops were hit, and the exit path is where the lane then went wrong. `BLIND_LANE_STOP_OUT_20261119.md`
  holds what happened and the correction, which is not on the host yet.
- **The principal is `Interactive`.** The lane's task, like lane 2's, is registered for the logged-on user: after a
  reboot with nobody logged on, `StartWhenAvailable` will not start it, and the terminal's own startup task is
  logon-triggered as well. `RunLevel Highest` fixes the identity-file permission; it does not fix that. The host's own
  check for a trader that runs without an interactive logon is therefore still red for this lane.
- **The ladder is the 2026-10-04 marking** (`data/l2l-levels.json`, `generated_at_utc 2026-10-04T16:14:19Z`). The lane
  reads whatever the published file holds and invents no line, so the reachable setups are an artefact of that
  marking: `BTCUSD` at `64,792` sits `3,773` points below its lowest rung `68,564.96`, watches that one line only, and
  cannot state a short from it because no original line is left below to aim the 5R target at.
- **The weekend.** Nothing in the EURUSD, XAUUSD or US100.cash snapshot will change until those markets reopen; the
  first post-open sequences are the first case the new session rule will decide, and the first one worth reading is
  whichever completes three legs after the open.
- **Publish lag.** The lanes publisher runs on a 600-second floor, so the strip can trail a tick by up to about ten
  minutes; the heartbeat's own `at_utc` is what dates the row, not the commit.

## 9. Since the arming: the stop that was not an ending

Added 2026-11-19, from the host's own state file and feed for the 16th to the 19th. Three of the lane's tickets filled
and were closed at their own stops — EURUSD `200695485` at 1.10115, US100.cash `200695492` at 27697.63, XAUUSD
`201323839` at 3840.21 — and none of the three ended the pair's trade. The pair re-selected around the market, the
deviation on the new line was confirmed, and the run then refused it because `decide` was still holding the finished
trade at the old level: a put-back there is a buy at the far side of a market that had left the line. The lane
therefore waited, tick after tick, on a trade the account had already closed. The fix reads a stop as an ending on
this lane alone and is committed in `live-trading/blind-stop-fix-20261119`; it was deployed to `C:\ftmo3` on
2026-11-19 at 16:56:48Z (lane branch fast-forwarded `d434fabe..441c308f`, trader sha256 `46020D67...A4F306A`), and
`BLIND_STOP_OUT_DEPLOY_20261119.md` is that deployment's own record: the three rows ended `stop-fill` on the first
tick, and EURUSD took a fresh short at 1.09782 on the pair's then-current line on the second.
