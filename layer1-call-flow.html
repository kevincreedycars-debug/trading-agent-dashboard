How the calls are made

Seven steps every refresh: the facts are saved once, each of the eight Layer 1 agents reads only its own rulebook and posts one 24-hour call, then one Layer 2 code node pairs those calls against USD - and nothing later can change an earlier call.

The whole chain · same order every run

From collected facts to a published call

Steps 01 to 03 happen once for the whole system, step 04 splits the eight assets into their own sealed agents, steps 05 to 07 pair the finished calls and publish them.

  1. 01 · TRIGGER Master Orchestrator Refresh button or a manual run starts the chain. webhook · refresh
  3. 02 · COLLECT Collectors + Eco Events One collector per market plus the economic calendar. FRED · Coinbase · Finnhub
  5. 03 · STORE Supabase market_snapshots Every collector writes the same newest shared row. newest usable row wins
  7. 04 · SEALED LAYER 1 Eight independent agents Own rulebook and newest usable facts only. 8 calls, kept apart
  9. 05 · STORE Supabase agent_outputs One new row per asset per run, kept as written. insert only
  11. 06 · LAYER 2 Pair selection One code node pairs the finished calls with USD. never recomputes
  13. 07 · PUBLISH Dashboard Writer → GitHub Writes the files the dashboard reads to GitHub. layer1 · layer2 · status

Step 04 in detail

Inside one Layer 1 agent

The same nine nodes run for every asset · logic/agent_<asset>_direction.md

  1. Called by the orchestratorIt runs as a sub-workflow: only when the chain runs.
  2. Read the newest factsSupabase Get Many pulls market_snapshots; the newest usable row wins.
  3. Build this asset's input packKeeps only the fields this asset needs; missing facts score neutral.
  4. Fetch its own rulebookIt downloads its logic file from GitHub, so it scores committed rules.
  5. Combine rulebook and factsRulebook text and input pack are joined before the model is asked.
  6. Ask the model for factor signalsOpenAI gpt-4.1-mini must answer strict JSON: one signal per factor.
  7. Parse the answerA code node rejects anything that is not the expected JSON.
  8. Calculate conviction in codeThe deterministic gate sets the 24-hour direction and conviction.
  9. Write the callOne row into agent_outputs: direction, conviction, factor breakdown.

Step 06 in detail

How Layer 2 picks a pair

No rulebook and no model: one code node over the finished Layer 1 rows

  1. Read the stored callsNewest 24-hour row per agent from Supabase agent_outputs.
  2. Pair each asset with USDSeven pairs, named under this list.
  3. Average the two convictionsconfidence = round((base + USD) / 2), clamped to 0-100.
  4. Keep only a disagreeing pairBoth legs 60 or more, neither with no clear bias, opposed.
  5. Rank them, then write the fileRank 1..n, then write trade_opportunities and avoid_today.

Base bullish with USD bearish reads BUY; the reverse reads SELL.

Live pairs: EUR/USD · XAU/USD · XAG/USD · BTC/USD · NQ/USD · WTI/USD · GBP/USD → data/layer2.json.

The guarantees the design holds to

What is always true

  • One rulebook each. An agent reads only its own logic document and the newest usable facts, never another agent's answer.
  • One call each. Every agent writes exactly one 24-hour call per usable run. A stale or unusable snapshot produces no row at all.
  • Code decides conviction. The model returns factor signals only. The deterministic gate sets direction and conviction, so the same facts give the same call.
  • Layer 2 only combines. It reads finished Layer 1 calls, averages the two legs of a pair and never recomputes one.
  • A pair is a selection, not an order. Nothing downstream of data/layer2.json places a trade.
  • Research never writes back. Backtests and replays work on copies and cannot touch a live call.

Limits, stated on the page itself

Read this page honestly

  • The saved exports are a partial mirror. The Layer 2 and Writer flows in this repo still name only the original five assets, while the live data/layer2.json names seven pairs - read data/*.json, not exports/.
  • Three rulebooks still carry draft headers. SILVER, WTI and GBP are marked inactive or research-only, yet both layers use them. Treat those calls as unproven.
  • One extra data path. The WTI agent is the exception: the shared snapshot has no WTI columns, so it reads the FRED crude series itself just before scoring.
  • The pair number is an average, not a probability. It is the mean of two Layer 1 convictions, on a different scale from either leg. It is not a chance a trade wins.
  • A dormant path can outrank the gate. If a Layer 1 row carries model-authored today_call direction or confidence, Layer 2 prefers it. Null for all eight agents today.
  • A published call is not a proven edge. This page shows how the calls are made, not whether they are right.
